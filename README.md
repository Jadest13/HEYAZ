# HEYAZ

React + Vite 웹, Expo 기반 React Native 앱, Hono API 서버를 포함하는 TypeScript monorepo입니다. 화면은 Emotion 및 Emotion Native를 사용합니다.

## 실행

전체 프로젝트와 서버 개발에는 Node.js 24 이상을 사용합니다. 저장소 루트에서 실행하세요.

```sh
npm install
npm run dev
```

웹: http://localhost:5173

API 서버는 별도 터미널에서 `npm run dev:server`로 실행합니다. 기본 주소는 `http://127.0.0.1:3000`, OpenAPI 문서는 `/openapi.json`입니다. 기본 PGlite DB는 파일에 저장되며 별도 DB 설치 없이 사용할 수 있습니다. 기존 Web/Native는 아직 API에 연결되지 않았습니다.

```sh
npm run build
npm run typecheck
npm run lint
npm test
npm run android
npm run start -w @heyaz/native
```

Native는 Expo SDK 54 기반이며 Android 에뮬레이터 또는 호환 개발 환경이 필요합니다. iOS 로컬 빌드는 macOS가 필요합니다. Expo prebuild 전에는 android/ios 생성물을 저장하지 않습니다.

## 구현 범위

- Web: 온보딩/프로필, 대시보드, 주간/월간 계획, 계획 편집, 운동별 세트 기록 및 교체, 휴식 타이머, 운동 결과, 월별 기록 조회, 기간별 분석, AI 채팅과 계획 변경 승인, 신체 기록/차트, Burning Day 설정/운동 풀/진행/리포트.
- Native: 홈/계획/AI 코치/기록/마이 탭, 주간·월간 카드/탭 보기와 운동 수치 편집, 실제 수행값으로 세트 기록, 체중 입력, 체력 확인, 심전도 기록 보기, 테스트 설정. 전체 계획 구성 편집과 분석, Burning Day 실행 및 네이티브 휴식 타이머는 후속 구현 범위입니다.
- Shared: 명시적 도메인 타입, 디자인 토큰, 저장소 계약, 공통 상태, 계획 검증 및 버전 충돌 검사, Mock AI, Burning Day 일정 생성, 계산 함수.
- Server: 프로필·계획·운동 세션·세트·신체 기록·체력 확인·Burning Day·대시보드·분석·코치 API 32개, PostgreSQL/PGlite 저장소, 인증된 사용자별 분리, 요청 재전송 및 버전 충돌 처리. `packages/contracts`에 API 스키마와 타입을 둡니다.

## 데이터와 AI

추가 웹 화면: `/design-system/typography`, `/design-system/color`, `/design-system/component`에서 실제 디자인 토큰과 컴포넌트를 확인합니다. `/ai-coach`가 코치의 새 주소이며 `/coach`는 자동 이동합니다.

`/my-page`는 임시 로그인 후 사용하는 마이페이지입니다. 로그인 버튼은 모달을 열고, 임시 로그인은 sessionStorage에 현재 탭의 테스트 상태만 저장합니다. 카카오·네이버·구글 버튼은 준비 중 상태로 비활성화되어 있으며 외부 인증 요청을 보내지 않습니다. 로그아웃은 운동 데이터를 삭제하지 않습니다.

신체 변화 차트는 여러 지표를 동시에 선택할 수 있습니다. 실제 값 모드는 공통 날짜/숫자 축에 원래 값을 표시하며 각 지표의 단위는 범례에 표시합니다. 변화율 비교는 각 지표의 첫 측정 대비 백분율로 표시합니다. 측정하지 않은 값은 0으로 대체하지 않고 선을 끊어 표시합니다. 날짜 버튼으로 실제 값을 확인할 수 있습니다.

첫 화면의 루틴은 편집 가능한 예시 계획입니다. 수행 기록과 신체 기록은 빈 상태에서 시작합니다. Web은 localStorage, Native는 AsyncStorage에 저장합니다. 두 앱 간 데이터는 동기화되지 않습니다. 브라우저 사이트 데이터를 지우면 기록도 삭제됩니다.

코치는 규칙 기반 Mock 서비스입니다. 운동 시간 변경/계획 생성/기록 요약을 지원하며 실제 AI API는 호출하지 않습니다. 변경안은 승인 시만 저장되고, 계획 버전이 달라지면 적용이 거절됩니다.

칼로리는 체중·시간·기본 MET를 사용하는 범위 추정입니다. Burning Day의 부분 완료 시간은 설정 시간의 절반으로 추정합니다. 골격근량은 실제 입력값만 표시합니다.

## 구조

`apps/web`과 `apps/native`에는 플랫폼 부트스트랩과 저장소 어댑터를 둡니다. 모든 앱 화면과 컴포넌트는 `packages/app/src`에서 관리하며, `navigation`은 플랫폼별 라우팅과 앱 레이아웃입니다. `.web.tsx`와 `.native.tsx`로 플랫폼 표현을 분리합니다. `ExerciseFields.tsx`는 Emotion Native와 React Native 기본 요소를 사용해 실제로 양쪽에서 공유하며 웹에서는 React Native Web으로 렌더링합니다. 기존 DOM 전용 레이아웃은 Emotion Web을 유지합니다.

## 신규 운동·코치 기능

- 운동 계획: 선택 카드/탭 중앙 정렬, 부드러운 가로 이동, 주간 탭 전체 폭, 오늘 표시. 모션 감소 설정을 켜면 즉시 이동합니다.
- 운동 입력: 중량 근력 운동은 세트/횟수/중량/휴식, 맨몸 근력 운동은 세트/횟수/휴식, 시간 운동은 세트/시간/휴식을 사용합니다.
- 체력 확인: `/assessment`에서 편안하게 수행한 값을 기록하고 코치의 시작 계획을 요청합니다. 규칙 기반 데모는 수행값의 약 70%를 제안하며 체력 등급이나 의료 판정을 내리지 않습니다. 제안은 승인 전까지 적용하지 않습니다.
- 운동 기록: 파란 직선(없음), 초록 작은 파동(일부 수행), 노란 파동(완료), 빨간 큰 파동(완료 후 다른 수행 기록도 있음). Burning Day 완료/부분 완료 이벤트가 있으면 불꽃 아이콘을 표시합니다. 달력/연속 카드 보기를 지원합니다.
- 코치 이용량: 무료는 첫 이용부터 15일 주기 5회, 유료 테스트는 기기 현지 시간 매월 1일 기준 100회입니다. 플랜을 전환해도 두 사용량을 보존합니다. 운동 외 질문도 최초 요청은 차감하며, 운동 외 판정 또는 추가 질문 후 이어지는 수정은 최대 3회 무료입니다. 정상 답변을 받으면 무료 수정 자격이 종료됩니다. 서비스 오류는 차감하지 않습니다.
- 설정: `/settings`의 테스트 섹션에서 유료 플랜 ON/OFF, 확인 후 데이터 초기화, 디자인 시스템 진입을 제공합니다. 초기화는 해당 앱 데이터만 지우고 다른 사이트 저장소는 건드리지 않습니다.

클라이언트의 운동 외 질문 판별과 이용 제한은 현재 로컬 Mock 정책입니다. 새 서버에는 서버 시각·인증·사용량 원장과 같은 규칙의 Mock 코치를 구현했습니다. 클라이언트 연결, 실제 AI 분류 및 결제는 후속 작업입니다.

서비스 교체 지점: `services/ai`, `services/storage`, `services/notification`. 현재 전체 로컬 상태 단위 저장소를 사용하며 서버 연결 단계에서는 도메인별 Repository 및 동기화 정책을 구현해야 합니다.

## 배포와 남은 통합

웹 빌드 결과는 `apps/web/dist`에 생성됩니다. 정적 호스팅 서버에서 모든 앱 경로를 `/index.html`로 rewrite해야 합니다. 예: Nginx `try_files $uri $uri/ /index.html;`.

운영 서버에는 배포하지 않았습니다. 새 API에 DB 저장·사용자별 데이터 격리·개발용 인증·OIDC 토큰 검증·코치 응답 검증을 구현했습니다. Web/Native 연결, 로그인 제공자 및 실제 AI 연결, 운영 백업, 결제·Push·Health 연동은 남아 있습니다. API 비밀키는 서버 환경 변수로 관리합니다.

운영 전 후속 작업: Native 기능 동등성, 날짜별 계획 예외/알림 편집, Burning Day 피로도·부위 기반 가중치와 실제 수행 시간 측정, 더 세부적인 운동별 PR·중량 차트, 알림 권한 및 백그라운드 예약, 실제 기기 QA.

2026-09-08 검증: Web 및 Native TypeScript 검사, ESLint, 도메인/코치 서비스 테스트 19개, Web 프로덕션 빌드와 Android용 JavaScript/Hermes 번들 내보내기가 통과했습니다.

별도 테스트 주소에서 브라우저로 온보딩, 주간/월간 카드·탭 전환, 코치의 운동 외 질문 차감과 무료 수정, 계획 변경 승인, 유료 플랜 토글, 임시 로그인 모달, 체력 결과 저장 및 코치 연결, 기록 달력·카드 전환, 체중/BMI 동시 선택을 확인했습니다. 390px 화면에서 가로 넘침을 검사하고, 화면 크기 변경 뒤 선택 카드 중앙 오차가 0px임을 확인했습니다. 초기 화면을 막던 지연 로딩 초기화 순서와 모바일 날짜 화살표 줄바꿈을 수정했습니다.

Android 번들 생성은 실제 기기 실행 검증과는 다릅니다. 연결된 Android 기기는 없었으며 Android/iOS 기기 실행 검증과 위에 명시한 Native 기능 동등성 작업은 남아 있습니다.

초기 설치에서 npm audit가 의존성 취약점 16건(중간 7건, 높음 9건)을 보고했습니다. 운영 배포 전 Expo 호환성을 유지하는 업데이트 및 재검토가 필요합니다. 호환성을 깨뜨리는 강제 업데이트는 적용하지 않았습니다.
